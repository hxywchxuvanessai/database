# databse
資料庫專題

## 雇主「雷」達

資料庫專題，目標是讓求職者查詢雇主的勞動法令裁罰紀錄，並逐步加入地圖、避雷指數、企業比較和 AI 說明。

- [專題簡報](docs/雇主雷達-專題簡報.pdf)
- [勞動裁罰原始 CSV](data/raw/A17000000J-030225-svj.csv)，含 79,580 筆紀錄。公告日期和處分日期各為 8 位數字，31,007 筆罰鍰金額空白。
- [全國營業（稅籍）登記資料 ZIP](data/raw/BGMOPEN1.zip)，取自[政府資料開放平臺資料集 9400](https://data.gov.tw/dataset/9400)，依政府資料開放授權條款第 1 版提供。2026-11-23 下載的 UTF-8 CSV 有 1,716,095 筆資料列，其中 1,716,094 筆具備不重複、格式為 8 位數字的統一編號。

## 兩人一起做的第一步

先完成一條可展示的流程：**輸入事業單位名稱 → 查到裁罰紀錄 → 顯示處分日期、違反法條和罰鍰金額**。

1. **資料庫同學**開 `feat/import-penalties` 分支。建立 PostgreSQL 暫存表，將 CSV 的九欄依原順序設為文字欄位。從 repo 根目錄用 `psql` 的 `\copy` 匯入，指定 `FORMAT csv, HEADER true, ENCODING 'UTF8'`。用 `SELECT COUNT(*)` 驗證是 79,580 筆。轉成正式表時，先確認日期格式，再將日期轉成 `date`、金額轉成整數，金額空白保留為 `NULL`。
2. **後端／App 同學**開 `feat/employer-search` 分支。先和資料庫同學約定查詢欄位，再用 C++/Crow 建立名稱搜尋 API。第一版回傳事業單位名稱、處分日期、違反法條和罰鍰金額，讓 Flutter 先做搜尋框與結果清單。畫面上將空白金額顯示為「未提供」。
3. **一起驗收**。用 CSV 中的事業單位名稱查詢，挑有金額和無金額的紀錄，核對畫面結果；再測一次查無資料的情況。各自推送分支、開 Pull Request，讓對方看過再合併。

後續再確認商工登記資料能否可靠對應裁罰紀錄，補上地址與地圖。接著依簡報定義並測試避雷指數，再做企業比較、AI 說明和 Android 實機測試。

## 驗證 20 萬筆

把營業登記匯入 `business_registrations` 表，統一編號用文字欄位 `tax_id`，以保留前導零。暫存表匯入後應先檢查格式不合的那一列，再匯入正式表。用以下查詢驗收符合格式的不重複統編：

```sql
SELECT COUNT(DISTINCT tax_id) AS unique_businesses
FROM business_registrations
WHERE tax_id ~ '^[0-9]{8}$';
```

此版本預期為 1,716,094 筆。裁罰紀錄另存一張表，原始裁罰 CSV 沒有統編。串接時可先比對標準化名稱，再核對地址或其他資料。名稱對應多筆時保留待確認狀態，避免把裁罰紀錄錯掛到另一家公司。

若老師接受營業登記資料列計入，單靠這張表即可超過 20 萬筆。若要求 20 萬筆都必須是裁罰紀錄，目前的裁罰 CSV 有 79,580 筆，還需補充至少 120,420 筆不重複的裁罰紀錄。
